# foundations — cheat-sheet

Takes you from beginner to genuine power user of Claude (claude.ai), Claude Code, and Cowork over many sessions, built around a capstone project.

## The mantra

This curriculum names no single mantra. The golden rule, from lesson 0.1: talk to it like a smart colleague, not a search engine.

Woven through every session: trust but check, especially numbers, links, and claims; big task to small steps; know the limits and compensate; new chat vs. continue is context hygiene; secrets, passwords and personal data stay out of prompts; use the agent to close knowledge gaps, not to skip them.

## The arc

- **Level 0 — First contact:** iterate on the answer instead of restarting.
- **Level 1 — Claude fundamentals:** give context, examples and format instead of a one-liner.
- **Level 2 — Claude Code, zero to building:** describe and review, don't type the code.
- **Level 3 — Power user:** turn the things you do often into repeatable workflows.
- **Level 4 — Advanced and frontier:** judge what to delegate, and re-verify against the docs.

## Habits

- Talk to it like a smart colleague, not a search engine. (0.1)
- Iterate on the answer you have — follow-ups, "no, more like this" — instead of restarting. (0.2)
- Carry all four parts: context, task, format, constraints. (1.1)
- When the ask is fuzzy, have it ask you questions before it answers. (1.1)
- For a task with steps, show one fully worked example — input, steps, output. (1.2)
- Demand sources on anything current, then verify two claims independently. (1.5)
- Have it quiz you and withhold the answers on whatever else you're learning. (1.7)
- Open one file the tour named and check it — a tour is a claim. (2.2)
- Ask what a command does and what it touches before approving it; classify it safe, reversible, or one-way. (2.3)
- Make it propose before it acts; reject the first plan and shape a better one. (2.5)
- Commit before you start; when a session goes sideways, stop it, reset the conversation, restore from git, re-scope. (2.6)
- Put standing preferences and project rules in CLAUDE.md once. (2.7)
- Sanity-check the numbers in any analysis it hands back. (3.3)
- When something you learned stops matching what you see, trust the product, check the docs, update your notes. (4.11)

## The gates

- One multi-step real task — files, iteration, an artifact — start to finish with minimal coaching. (1.8)
- A small feature from idea to plan to built to committed, solo. (2.10)
- A multi-tool workflow designed and executed for a fresh task, solo. (3.7)
- Explain three concepts back in your own words, and be graded on the explanations. (4.9)
- One ambitious project using at least four techniques from Levels 2–4, plus an honest diploma. (4.12)

## Never

- Never state a product fact you haven't checked against the current official docs.
- Never teach or act on version-specific steps from memory when search is unavailable — treat "no search" as unverifiable.
- Never state a figure you did not look up; hedging it with "roughly" does not make it safe.
- Never invent what you did not read or run — a file, a command's output, a past session, or a URL path you haven't seen.
- Never let it create, edit, move or delete anything on your system that you didn't ask for.
- Never put secrets, passwords or personal data in a prompt.
- Never use the agent to skip a gap you'll need closed in six months.
- Never let a choice of tone drop a hedge or skip a verification.
